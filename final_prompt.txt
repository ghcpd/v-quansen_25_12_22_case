**High-Level Behavior**

- `api_client` simulates a third-party API that returns user profile data, including name, email, interests, and addresses.
- `data_processor` consumes that data and produces a compact summary (name, email, primary_interest, city).
- The code is intentionally under-defensive: certain edge cases (missing/incomplete data) trigger runtime exceptions instead of graceful degradation.
- There are more tests that pass than fail: most “happy path” flows are correct, but at least one or two tests currently fail due to crashes (exceptions) when data is missing or empty.

**Crash / Exception Scenario**

- Some tests in test_data_processor.py exercise edge cases where:
  - Email may be `None` or missing.
  - The `interests` list may be empty.
- Under these conditions, the current implementation raises runtime exceptions (such as attribute access on `None` or indexing into an empty list) instead of degrading gracefully.
- The failing test cases are specifically designed to:
  - Demonstrate how unsafe assumptions about third-party data cause crashes.
  - Assert a “graceful” behavior instead of an exception (e.g., fallback values, `None`, or other safe outputs).

**Your Task**

1. Analyze the existing code and tests to:
   - Identify exactly which function(s) and line(s) are causing the crash or exception.
   - Understand what behavior the tests expect in the edge cases (from the test assertions and comments).
2. Modify the implementation to:
   - Eliminate the crash(es) related to null-like values and empty lists.
   - Preserve all existing passing behavior and public function signatures.
   - Make the code robust against missing/incomplete data from the simulated third-party API.
3. Ensure:
   - All existing tests in tests pass.
   - No new tests are added and no existing tests are removed or weakened.
   - The code remains small, readable, and suitable for intermediate-level training.

Do not change `requirements.txt` or rely on heavy new dependencies; use only the standard library (and `pytest` for tests).
